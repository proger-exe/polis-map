# Техническое задание: система околополитического ролплея с интерактивной картой

## 1. Назначение проекта

Разработать систему для околополитического ролплея, где игроки или группы игроков могут создавать государства, контролировать территории, совершать политические действия, колонизировать новые земли и взаимодействовать через Telegram.

Система должна быть привязана к визуальной карте мира: изображению, на котором отображаются территории государств, точки действий, колонии, спорные зоны и важные объекты.

Проект не должен быть симулятором реальной политики в прямом смысле. Это игровая ролевая система с политическими механиками, ограничениями и контролируемым конфликтом.

## 2. Основная идея

Игровой мир делится на территории, которые отображаются на карте. Каждое государство имеет цвет, название, правителя, участников, столицу, границы и набор политических статусов.

Игроки могут:

* создавать государства;
* захватывать или колонизировать территории;
* заключать союзы;
* объявлять конфликты;
* вести дипломатические действия;
* строить политическую историю сервера;
* видеть актуальное состояние мира на карте;
* подтверждать действия через Telegram.

Карта должна быть не просто картинкой, а интерактивной системой координат, где каждое действие привязано к конкретной точке или области.

## 3. Формат системы

Рекомендуемая архитектура:

* Web-интерфейс для карты и администрирования;
* Telegram-бот для привязки игроков, уведомлений и подтверждения действий;
* Backend API для хранения данных, обработки действий и генерации карты;
* Панель маппера для редактирования территорий;
* База данных для государств, игроков, территорий и политических событий.

Система может быть связана с Minecraft-сервером, но ядро должно быть независимым: карта, государства и действия должны работать отдельно от Minecraft-плагинов.

## 4. Роли пользователей

### 4.1 Игрок

Обычный участник ролплея.

Возможности:

* привязать Telegram;
* вступить в государство;
* просматривать карту;
* подавать заявки на действия;
* участвовать в политических событиях;
* получать уведомления.

### 4.2 Лидер государства

Игрок, управляющий государством.

Возможности:

* инициировать дипломатические действия;
* объявлять претензии на территории;

* подтверждать внутренние решения;
* управлять столицей и основными точками государства.

### 4.3 Маппер

Ответственный за карту и территории.

Возможности:

* загружать базовое изображение карты;

* задавать спорные зоны;

### 4.4 Модератор

Возможности:

* подтверждать заявки;

* выдавать ограничения;
* замораживать конфликты;
* редактировать спорные ситуации;
* просматривать журнал событий.

### 4.5 Администратор

Полный доступ к системе.

Возможности:

* сбрасывать карту;
* редактировать все государства;
* управлять Telegram-ботом;
* смотреть технические логи.

## 5. Карта реальных действий

### 5.1 Базовая карта

Карта должна использовать изображение как основу.

Требования:

* поддержка загрузки изображения карты;
* хранение размеров изображения;
* координатная система относительно изображения;
* масштабирование без потери привязки объектов;
* возможность заменить изображение без полного уничтожения данных, если размер и пропорции совпадают.

Координаты объектов должны храниться не в пикселях, а в нормализованном виде:

```text
x = позиция_по_X / ширина_изображения
y = позиция_по_Y / высота_изображения
```

Пример:

```json
{
  "x": 0.421,
  "y": 0.683
}
```

Это позволит сохранять привязку даже при изменении размера изображения. Чудо инженерии, человечество почти победило кривые координаты.

### 5.2 Объекты на карте

На карте должны отображаться:

* территории государств;
* столицы;
* колонии;
* спорные территории;
* точки боевых или политических действий;
* нейтральные зоны;
* заблокированные зоны;
* исторические события;
* административные границы.

### 5.3 Карта действий

Каждое политическое действие может быть привязано к:

* точке;
* территории;
* границе между территориями;
* столице;
* колонии;
* спорной зоне.

Пример действия:

```json
{
  "type": "colonization_request",
  "actor_state_id": 5,
  "target_area_id": 18,
  "point": {
    "x": 0.312,
    "y": 0.744
  },
  "status": "pending"
}
```

## 6. Отрисовка территорий государств

### 6.1 Территории как полигоны

Каждая территория должна быть полигоном, состоящим из набора точек.

Пример:

```json
{
  "territory_id": 12,
  "points": [
    { "x": 0.12, "y": 0.20 },
    { "x": 0.18, "y": 0.22 },
    { "x": 0.17, "y": 0.31 },
    { "x": 0.10, "y": 0.29 }
  ]
}
```

Требования:

* создание полигона кликами по карте;
* редактирование каждой точки;
* добавление новых точек между существующими;
* удаление точек;
* перемещение всей территории;
* изменение цвета территории;
* настройка прозрачности заливки;
* настройка толщины границ.

### 6.2 Гибкое редактирование точек

Маппер должен иметь возможность:

* перетаскивать вершины полигона;
* добавлять промежуточные вершины;
* удалять лишние вершины;
* менять порядок точек;
* включать режим точной настройки координат;
* откатывать изменения.

Для каждой территории желательно хранить историю версий:

```json
{
  "territory_id": 12,
  "version": 4,
  "changed_by": 2,
  "changed_at": "2026-06-13T18:00:00Z",
  "reason": "Колонизация северной зоны"
}
```

### 6.3 Типы территорий

Система должна поддерживать типы территорий:

| Тип          | Описание                        |
| ------------ | ------------------------------- |
| `state_core` | Основная территория государства |
| `colony`     | Колония                         |
| `neutral`    | Нейтральная территория          |
| `disputed`   | Спорная территория              |
| `occupied`   | Оккупированная территория       |
| `protected`  | Защищённая зона                 |
| `locked`     | Закрытая для действий зона      |

## 7. Государства

### 7.1 Модель государства

Государство должно иметь:

* ID;
* название;
* короткое название;
* цвет на карте;
* герб или иконку;
* описание;
* форму правления;
* лидера;
* участников;

* список территорий;
* дату основания;
* статус активности;

Пример:

```json
{
  "id": 1,
  "name": "Северная Республика",
  "short_name": "СР",
  "color": "#4A90E2",
  "leader_id": 15,
  "capital_point": {
    "x": 0.51,
    "y": 0.44
  },
  "government_type": "republic",
  "status": "active"
}
```

### 7.2 Статусы государства

Возможные статусы:

| Статус      | Значение                         |
| ----------- | -------------------------------- |
| `active`    | Активное государство             |
| `frozen`    | Заморожено администрацией        |
| `collapsed` | Распалось                        |
| `occupied`  | Частично или полностью захвачено |
| `protected` | Временно защищено                |
| `pending`   | Ожидает подтверждения            |

## 8. Колонизация территорий

### 8.1 Общая логика

Колонизация — это процесс получения контроля над нейтральной или слабоконтролируемой территорией.

Колонизация не должна быть мгновенной, иначе игроки за 20 минут превратят карту в геополитический борщ.

### 8.2 Условия колонизации

Государство может подать заявку на колонизацию, если:

* государство активно;
* лидер привязан к Telegram;
* целевая территория имеет статус `neutral` или разрешённый для колонизации;
* территория не находится в защищённой зоне;
* у государства нет активного лимита на колонизацию;
* выполнены требования по расстоянию или соседству;
* заявка не нарушает лимиты размера.

### 8.3 Возможные модели колонизации

#### Вариант A: Колонизация через заявку

1. Лидер выбирает территорию.
2. Подаёт заявку.
3. Модератор или маппер проверяет её.
4. После подтверждения территория меняет статус на `colony`.

#### Вариант B: Колонизация через очки влияния

У государства есть очки влияния.

Формула:

```text
доступное_влияние = базовое_влияние + активность_игроков × коэффициент - штрафы
```

Пример:

```text
influence = 10 + active_players * 2 - penalties
```

Колонизация стоит определённое количество влияния:

```text
cost = base_cost + area_size * size_multiplier + distance_penalty
```

Пример:

```text
cost = 5 + territory_area * 0.8 + distance_from_capital * 0.3
```

#### Вариант C: Колонизация через реальные действия

Игроки должны выполнить игровое условие:

* построить аванпост;
* провести экспедицию;
* оставить заявку с координатами;
* удерживать точку определённое время;
* получить подтверждение маппера.

### 8.4 Стадии колонизации

| Стадия        | Описание                |
| ------------- | ----------------------- |
| `requested`   | Заявка подана           |
| `approved`    | Заявка одобрена         |
| `in_progress` | Колонизация началась    |
| `contested`   | Территория оспаривается |
| `completed`   | Колонизация завершена   |
| `rejected`    | Заявка отклонена        |
| `cancelled`   | Заявка отменена         |

### 8.5 Ограничения колонизации

Рекомендуемые ограничения:

* не больше 1 активной колонизации на государство;
* задержка между колонизациями: 24–72 часа;
* нельзя колонизировать территорию без связи с основной землёй, если не разрешены морские/дальние колонии;
* нельзя колонизировать чужую территорию без конфликта;
* нельзя захватывать столицу через обычную колонизацию;
* нельзя создавать анклавы без отдельного разрешения;
* нельзя колонизировать защищённые зоны.

## 9. Политические действия

### 9.1 Базовые действия

Система должна поддерживать следующие действия:

| Действие                  | Описание                               |
| ------------------------- | -------------------------------------- |
| Создание государства      | Регистрация нового государства         |
| Вступление в государство  | Игрок становится участником            |
| Выход из государства      | Игрок покидает государство             |
| Назначение лидера         | Передача власти                        |
| Изменение формы правления | Ролевая смена устройства               |
| Перенос столицы           | Смена главной точки государства        |
| Колонизация               | Получение новой территории             |
| Претензия                 | Заявка на спорную территорию           |
| Союз                      | Дипломатический договор                |
| Нейтралитет               | Отказ от конфликта                     |
| Конфликт                  | Официальное противостояние             |
| Мирный договор            | Завершение конфликта                   |
| Санкция                   | Ограничение взаимодействия             |
| Распад государства        | Удаление или архивирование государства |

### 9.2 Статусы действий

Каждое действие должно иметь статус:

| Статус      | Значение         |
| ----------- | ---------------- |
| `draft`     | Черновик         |
| `pending`   | Ожидает проверки |
| `approved`  | Одобрено         |
| `rejected`  | Отклонено        |
| `active`    | Активно          |
| `expired`   | Истекло          |
| `cancelled` | Отменено         |

### 9.3 Лог действий

Все политические действия должны записываться в журнал.

Пример записи:

```json
{
  "id": 144,
  "type": "alliance_created",
  "actor_state_id": 1,
  "target_state_id": 3,
  "created_by": 15,
  "status": "approved",
  "created_at": "2026-06-13T18:00:00Z"
}
```

Журнал нужен обязательно. Без него любой спор превращается в «я такого не говорил», а это уже не ролплей, а бытовая катастрофа.

## 10. Ограничения политических действий

### 10.1 Общие ограничения

* Любое действие от имени государства может совершать только лидер или назначенный представитель.
* Игрок должен быть привязан к Telegram.
* Государство не может выполнять действия в статусе `frozen`.
* Действия с территориями требуют проверки маппера или модератора.
* Конфликты должны иметь причину.
* Нельзя объявлять конфликт государству, которое находится под защитой администрации.
* Нельзя создавать государства с оскорбительными, экстремистскими или провокационными названиями.
* Нельзя использовать реальные экстремистские символы и идеологии.
* Нельзя обходить лимиты через создание фиктивных государств.

### 10.2 Кулдауны

Рекомендуемые кулдауны:

| Действие             | Кулдаун          |
| -------------------- | ---------------- |
| Создание государства | 7 дней на игрока |
| Колонизация          | 24–72 часа       |
| Перенос столицы      | 7 дней           |
| Объявление конфликта | 48 часов         |
| Создание союза       | 24 часа          |
| Смена лидера         | 24 часа          |
| Подача претензии     | 24 часа          |

### 10.3 Лимиты

Рекомендуемые лимиты:

| Параметр                      | Значение                  |
| ----------------------------- | ------------------------- |
| Активных государств на игрока | 1                         |
| Лидерство одновременно        | 1 государство             |
| Активных колонизаций          | 1 на государство          |
| Активных конфликтов           | 1–3 на государство        |
| Союзов                        | ограничивается настройкой |
| Претензий на территории       | 3–5 активных              |

## 11. Telegram-привязка

### 11.1 Назначение

Telegram используется для:

* подтверждения личности игрока;
* уведомлений;
* подачи заявок;
* подтверждения политических действий;
* административных логов;
* оповещений о событиях.

### 11.2 Привязка аккаунта

Процесс:

1. Игрок получает код на сайте или в игре.
2. Пишет Telegram-боту команду `/start`.
3. Вводит код.
4. Система связывает Telegram ID с игровым аккаунтом.

Пример:

```text
/link ABCD-1234
```

После успешной привязки:

```text
Аккаунт успешно привязан.
Игрок: Sh3lbyCode
Telegram: @username
```

### 11.3 Telegram-команды

Минимальный набор команд:

| Команда        | Назначение                   |
| -------------- | ---------------------------- |
| `/start`       | Запуск бота                  |
| `/link <code>` | Привязка аккаунта            |
| `/profile`     | Профиль игрока               |
| `/state`       | Информация о государстве     |
| `/map`         | Ссылка на карту              |
| `/actions`     | Активные действия            |
| `/colonize`    | Подача заявки на колонизацию |
| `/diplomacy`   | Дипломатические действия     |
| `/confirm`     | Подтверждение действия       |
| `/cancel`      | Отмена действия              |
| `/admin`       | Админ-меню                   |

### 11.4 Уведомления

Бот должен отправлять уведомления:

* о создании государства;
* о новой заявке;
* об одобрении или отклонении действия;
* о начале колонизации;
* о споре за территорию;
* о новом союзе;
* о конфликте;
* об изменении границ;
* о решениях администрации.

### 11.5 Админ-чат

В отдельный Telegram-чат должны отправляться события:

* новые заявки на государства;
* заявки на колонизацию;
* спорные действия;
* изменения карты;
* попытки нарушения лимитов;
* ручные правки маппера;
* ошибки системы.

## 15. Генерация карты

Система должна уметь:

* отображать карту в браузере интерактивно;
* экспортировать карту в PNG;
* генерировать статичную карту для Telegram;
* показывать легенду государств;
* отображать дату последнего обновления.

Экспортируемая карта должна включать:

* территории;
* границы;
* столицы;
* названия государств;
* спорные зоны;
* легенду;
* подпись версии карты.

## 16. Безопасность и антиабуз

Система должна защищаться от:

* спама заявками;
* мультиаккаунтов;
* обхода кулдаунов;
* захвата карты через фиктивные государства;
* массовой смены границ без логов;
* удаления истории;
* несанкционированных правок маппера.

Обязательные меры:

* роли и права доступа;
* логирование всех изменений;
* подтверждение опасных действий;
* кулдауны;
* лимиты;
* ручное подтверждение спорных действий;
* резервные копии карты;
* история версий территорий.

## 17. Настройки баланса

Администратор должен иметь возможность менять:

* максимальное количество государств;
* лимиты территорий;
* кулдауны;
* стоимость колонизации;
* требования к созданию государства;
* максимальный размер колонии;
* правила соседства;
* правила конфликтов;
* длительность защиты новых государств;
* количество активных заявок.

Пример настроек:

```json
  "new_state_protection_days": 3,

```

## 18. MVP

### 18.1 Первая версия

В MVP должны входить:

* загрузка карты-изображения;
* отображение карты в web-интерфейсе;
* создание государств;
* создание территорий полигонами;
* редактирование точек территорий;
* базовая Telegram-привязка;
* заявки на колонизацию;
* подтверждение заявок модератором;
* журнал действий;
* экспорт карты в PNG.

### 18.2 Не входит в MVP

На первом этапе можно не делать:

* сложную экономику;
* войны с автоматическим расчётом;
* очки влияния;
* полноценные законы государств;
* автоматическую интеграцию с Minecraft;
* сложную систему населения;
* многоуровневую дипломатию.

## 20. Критерии готовности

Система считается готовой, если:

* карту можно загрузить и открыть;
* маппер может создать и изменить территорию;
* точки территории можно гибко двигать;
* государство может быть создано;
* государство отображается на карте своим цветом;
* Telegram-аккаунт можно привязать;
* лидер может подать заявку на колонизацию;
* модератор может подтвердить или отклонить заявку;
* после подтверждения карта обновляется;
* все действия записываются в журнал;
* карту можно экспортировать в PNG;
* спорное действие можно откатить по истории.

## 22. Главный принцип

Система должна не заменять ролплей, а структурировать его.

Игроки создают историю, а система:

* фиксирует действия;
* не даёт абузить;
* показывает карту;
* ограничивает хаос;
* делает конфликты понятными;
* сохраняет историю мира.

Иначе это будет не политический ролплей, а чатик с претензиями на Венский конгресс.
